# Data, State & Forms Rules

Detail for the data-layer directives summarized in `CLAUDE.md`:
client state (Zustand), the generated API client (Kubb), and forms +
validation.

## State management (Zustand)

- Default state library is Zustand. Stores live under `src/store/`.
- Keep store slices small — one slice per domain (auth, todos, ...).
- Server state goes through React Query hooks generated by Kubb. Do
  NOT duplicate server data into Zustand. Use Zustand only for
  client-owned state (UI state, form drafts, optimistic flags).

## API client (Kubb)

- Typed client + React Query hooks are generated from the OpenAPI
  spec into `src/openapi/`.
- NEVER hand-edit files under `src/openapi/`. Regenerate via
  `pnpm kubb` after the spec changes.
- Consume only via Kubb-generated hooks. Do not bypass with raw
  axios calls in feature code.

→ Codegen config: `kubb.config.ts`

## Forms & validation

- Forms: React Hook Form (`useForm`, `Controller`).
- Validation: Zod schemas + `@hookform/resolvers/zod`.
- Horizon `FormTextField` integrates with RHF out-of-the-box —
  prefer it over manual `Controller` wrapping for text inputs.
