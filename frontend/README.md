# Nextjs Service Boilerplate (`frontend-belajar-lintas-ronald`)

Opinionated Next.js 15 frontend boilerplate for S-Quantum Engine projects. Ships with the Horizon UI library, typed API clients generated from OpenAPI, an auth flow that works in both SSR and CSR modes, and MSW-powered mocking out of the box.

> Part of the [boilerplate-monorepo](../README.md). See the monorepo root for the cross-language overview.

## Stack

- **Framework** — [Next.js 15](https://nextjs.org/) (App Router) on React 19, with Turbopack aliases configured for SVG-as-component imports.
- **UI** — [`@squantumengine/horizon`](https://sqehorizon.squantumengine.com) is the **only** sanctioned component library (see [CLAUDE.md](CLAUDE.md)). Tailwind CSS handles layout/spacing.
- **Data layer** — [TanStack React Query](https://tanstack.com/query) with hooks generated by [Kubb](https://kubb.dev/) from your OpenAPI spec.
- **Forms & validation** — [React Hook Form](https://react-hook-form.com/) + [Zod](https://zod.dev/) (with a custom error map at [src/utils/zod.ts](src/utils/zod.ts)).
- **State** — [Zustand](https://zustand-demo.pmnd.rs/) (see [src/store/](src/store/)).
- **Mocking** — [MSW](https://mswjs.io/) wired through [src/utils/msw/](src/utils/msw/) and toggled via env.
- **Tooling** — TypeScript 5, ESLint 9 (flat config), Prettier (with Tailwind + classnames plugins), Husky, release-it.

## Getting Started

### Prerequisites

- Node.js 20+
- pnpm (the repo pins `cross-spawn`/`axios`/etc. via `pnpm.overrides`)

### Install

```bash
pnpm install
```

### Configure environment

Copy [.env-example](.env-example) to `.env` and fill in the values:

```bash
cp .env-example .env
```

| Variable                                          | Purpose                                                                              |
| ------------------------------------------------- | ------------------------------------------------------------------------------------ |
| `NEXT_PUBLIC_RENDERING_MODE`                      | `ssr` or `csr` — switches the auth/session strategy. Default: `csr`.                 |
| `NEXT_PUBLIC_BACKEND_URL`                         | Base URL for the backend API.                                                        |
| `NEXT_PUBLIC_API_MOCKING`                         | Set truthy to enable MSW handlers in [src/mocks/handlers.ts](src/mocks/handlers.ts). |
| `NEXT_OPENAPI_URL`                                | OpenAPI spec source for `pnpm generate:schema` (URL or local path).                  |
| `NEXT_OPENAPI_USERNAME` / `NEXT_OPENAPI_PASSWORD` | Basic-auth credentials for protected OpenAPI specs.                                  |
| `NEXT_PUBLIC_ENCRYPTION_KEY`                      | CSR-only key for encrypting localStorage session payloads.                           |
| `AUTH_COOKIE_SECRET`                              | SSR-only 32-char secret for cookie encryption.                                       |
| `NEXT_PUBLIC_ENABLE_REFRESH_TOKEN`                | `true` to enable automatic refresh-token rotation in middleware.                     |
| `NEXT_PUBLIC_APP_NAME`                            | Display name (defaults to `SQEBoilerplate`).                                         |

### Run

```bash
pnpm dev          # start the dev server
pnpm build        # production build (also required to verify Horizon builds cleanly)
pnpm start        # serve the production build
```

## Scripts

| Command                  | What it does                                                                                                      |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| `pnpm dev`               | Next.js dev server.                                                                                               |
| `pnpm build`             | Production build. **Must pass** — the CI pipeline halts on build failure.                                         |
| `pnpm lint` / `lint:fix` | ESLint with `--max-warnings=0`.                                                                                   |
| `pnpm prettier`          | Format the whole repo.                                                                                            |
| `pnpm schema:download`   | Pull the OpenAPI spec into `src/openapi/openapi.json` ([scripts/download-schema.ts](scripts/download-schema.ts)). |
| `pnpm generate:schema`   | Download spec → run Kubb → patch output → lint → format. **Run after backend changes.**                           |
| `pnpm release`           | Cut a release with [release-it](https://github.com/release-it/release-it) (no npm publish).                       |

## Key Capabilities

### Authentication (axis-driven multi-adapter)

The boilerplate ships **four auth-model adapters**, selected via the `auth` axis in `.boilerplate.yaml`. Each adapter is self-contained under `src/services/auth/<option>/`:

| Option | Use when | Notes |
|---|---|---|
| `jwt-refresh` (default) | Backend issues JWT access + refresh tokens with explicit expiry | Encrypted localStorage / httpOnly cookie storage; auto-refresh queue |
| `opaque-session` | Backend issues opaque session tokens (e.g. server-side session with TTL) | No client-side expiry decode; 401 → re-login |
| `oauth2-oidc` | OIDC provider (Auth0, Cognito, Keycloak, …) | TODO stub in v1.0.0 |
| `none` | Public app, no auth | All adapter methods throw or return null |

App code imports from `@/services/auth` (the index re-export). It MUST NOT import from `@/services/auth/<option>/...` directly.

Sample reference contracts per model live under [`docs/sample-contracts/`](docs/sample-contracts/) for backend implementers and MSW handler authors.

### Sample app pages (axis-driven pruning)

Two opt-in sample feature folders are controlled by the `sample-app` axis (`one_or_more`, `min=0`):

- `auth-flow` — `(auth)/login`, `(auth)/change-password`, and `(auth)/forgot-password` (the last is kept only when `auth=jwt-refresh`).
- `dashboard` — `(protected)/dashboard` (Horizon Card sample).

Production scaffolds can opt out of both by selecting `sample-app: []`.

### Switching auth model in monorepo dev

Edit [`src/services/auth/index.ts`](src/services/auth/index.ts) and change the literal `'./jwt-refresh'` to one of `'./opaque-session'`, `'./oauth2-oidc'`, `'./none'`. The active adapter changes immediately on the next `pnpm dev` reload. The SDLC plugin performs the same edit (plus deletion of inactive option folders) at scaffold time.

### Generated API client

The shipped `src/openapi/openapi.json` is a generic stub (auth + items CRUD) intended as a placeholder. Replace it with your backend's spec — either by setting `NEXT_OPENAPI_URL` and running `pnpm generate:schema`, or by overwriting the file directly and re-running Kubb.

[kubb.config.ts](kubb.config.ts) reads `src/openapi/openapi.json` and emits:

- TypeScript types under `src/openapi/types/`
- Zod schemas under `src/openapi/zod/`
- React Query hooks under `src/services/` (queries for `GET`, mutations for `POST`/`PUT`/`PATCH`/`DELETE`), grouped by OpenAPI tag.

The hooks use the shared fetcher at [src/services/fetcher/](src/services/fetcher/), which handles auth headers, token refresh queueing, and error parsing.

### MSW mocking

Toggled by `NEXT_PUBLIC_API_MOCKING`. The provider at [src/utils/msw/](src/utils/msw/) loads handlers from [src/mocks/handlers.ts](src/mocks/handlers.ts) before the app mounts.

### Horizon UI only

This project enforces Horizon as the single UI library. Read [CLAUDE.md](CLAUDE.md) and the component reference at `.claude/docs/horizon-components.md` before adding UI. **Do not** install MUI, Chakra, shadcn/ui, etc.

The root layout sets the theme via the `theme-hz-mining` class — change it in [src/app/layout.tsx](src/app/layout.tsx) to one of: `blue`, `green`, `magenta`, `neutral`, `orange`, `purple`, `red`, `teal`, `yellow`.

## Containerized run

The monorepo's root `compose.yml` includes a `frontend-belajar-lintas-ronald` service that builds from this directory's Dockerfile. From the repo root:

```bash
docker compose up -d frontend-belajar-lintas-ronald
curl http://localhost:3000/
```

Dev workflow still uses `pnpm dev` on the host; the container path is for smoke-testing the production image or running alongside a containerized backend.

## Conventions

- Run `pnpm build`, `pnpm lint:fix`, and `pnpm prettier` before opening a PR — CI will fail otherwise.
- Husky enforces pre-commit checks; do not bypass with `--no-verify`.
- Never edit anything under `src/openapi/` by hand. Re-run `pnpm generate:schema` instead.
- Commit messages follow conventional-commits (release-it generates the changelog from them).
